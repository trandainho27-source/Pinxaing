# 配置客户邮箱验证码

前台为可选登录，未配置发信服务时不影响游客购物。演示站提供单独的演示验证码体验，不能代替真实邮箱验证。

## 需要配置的两项

| 环境变量 | 内容 | 保存方式 |
| --- | --- | --- |
| RESEND_API_KEY | 你在 Resend 中创建的发送邮件 API Key | Secret，不填在代码或浏览器页面里 |
| EMAIL_FROM | `品香 <login@auth.pinxiang.lol>`，使用已验证的发件子域名 | 运行时环境变量 |

沿用既有 `INVENTORY_KEY` 对验证码做带密钥摘要；不要为开通邮箱而更换已有的账号加密密钥。验证码明文不存数据库、不进日志、不在真实发送接口响应中返回。

在 Resend 添加你拥有的发件域名，并按其要求配置 DNS 验证。随后在网站对应的运行环境设置上述两项，重新部署生效：

- ChatGPT Sites：在站点运行环境配置，原有数据库及密钥保持不变。
- 自己的 Cloudflare Worker：Worker → Settings → Variables and Secrets；与 Sites 是不同环境，需要分别配置。

接口使用 Resend 的 `POST https://api.resend.com/emails`，带授权与幂等请求头。官方参考：https://resend.com/docs/api-reference/emails/send-email 。无需前端 SDK 或邮件密码。

## 正式站仍提示邮箱登录不可用时

品香正式域名是 `https://pinxiang.lol`。客户登录入口为 `/account`，店主在 `/admin` 的「客户账号」页面可以查看「邮箱注册与登录」检测面板。面板逐项检查当前 Worker 实际读到的 `RESEND_API_KEY`、`EMAIL_FROM`、`INVENTORY_KEY`，分别标记「已设置」「未设置」「格式不正确」，不会显示密钥内容。只有店主能读取这些诊断。

Cloudflare 构建 API 令牌用于部署，不是 Resend 发信密钥；仅在构建变量中填写也不会使运行中的应用取得密钥。请在 `pinxiang-commerce → 设置 → 变量和机密` 中配置并保存部署，再点击后台「重新检测」。若加密密钥格式不正确，必须核对原值，不要因邮箱配置而更换已有库存加密密钥。

客户登录页进入时、重新回到该窗口时，以及未登录期间每 30 秒会刷新服务状态，并提供「重新检测登录服务」。连接失败单独提示重试，不会一直停在加载中；配置缺失时保留游客购物入口。店主检测面板中的「配置已就绪」不代表邮件已经实际送达，需要完成下方验收。

## 正式投递验收

1. 使用你自己控制的收件邮箱，在登录页申请验证码，确认收件与垃圾邮件目录中的显示正常。
2. 验证后应显示「邮箱已验证」，首次登录自动建立账号，后续使用同一邮箱仍登录同一账号。
3. 验证码 10 分钟内有效，单次使用，最多尝试 5 次；重发至少间隔 60 秒，成功登录将使该邮箱其他未使用验证码失效。
4. 验证登录后本人订单隔离、游客凭证绑定、退出所有设备、员工与客户会话隔离。
5. 正式商城使用独立数据库并关闭 `DEMO_MODE`。正式模式不能使用演示账号、演示验证码或模拟付款。

目前已用模拟邮件服务测试接口与运行时链路，没有发送真实邮件。只有运营方完成发信域名、密钥配置及真实投递验收后，才能视为邮箱服务可用。邮箱验证码适配不代表任何支付接口开通。
