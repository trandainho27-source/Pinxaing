# 实体商城验收记录

日期：2026-10-16。范围：从数字商品版本升级至实体商品商城，保留私人演示站和原仓库。

| 检查 | 结果 |
| --- | --- |
| TypeScript 类型检查 | 通过 |
| 业务自动化测试 | 60 项通过：22 项实体商城 / 升级检查，38 项历史模块回归 |
| 生产构建 | 通过；商城、订单、帮助、后台、商品详情与 API 路由生成 |
| workerd 演示模式 | 通过；4 个 SSR 页面、D1、登录、固定邮费、空地址、赠送账号、付款、发货、定时过期 |
| workerd 正式配置 | 通过；空数据库初始化、实体库存、账号导入、收款登记、发货和全部支付占位 |
| 数据库升级 | 先建立旧结构和旧订单，再追加新迁移，原凭证可继续查询交付；自定义品牌保留 |
| 邮费 | 后端固定 2000 分；忽略客户端价格和免邮参数；一单多商品只收一次 |
| 原子性与重复请求 | 同一凭证并发重试只有一个订单；争抢最后商品或最后账号只有一笔成功；失败事务不残留锁库或赠送分配 |
| 账号访问 | 创建即赠送、AES-GCM 加密、标识去重、订单密钥校验、后台不显示明文 |
| 取消与过期 | 商品数量仅释放一次；已赠送账号保持原订单归属 |
| 付款与配送 | 确认付款不发货；单号录入需已付款、权限与有效格式；重复同单号幂等，不提供轨迹 |
| 管理权限 | 店主、运营、客服按权限操作；收货信息仅发货前可修改；来源与 CSRF 校验 |
| 支付禁用 | 即使保留旧 TRC20 / HMAC / 货源变量，当前路由与定时任务也不发起网络请求 |
| 售后和退款 | 工单权限、回复持久化；退款仅登记，不发送资金、不回补库存、不回收赠送账号 |

历史回归测试会在隔离测试环境中直接调用保留模块，其中使用模拟链上或供应商响应。这不代表旧付款或采购在现行网站中启用；现行 Worker 验证明确要求外部支付和货源调用数为零。

## 验证边界

- 当前环境缺少 Sites 要求的浏览器控制能力，未进行浏览器点击、截图和移动端视觉验收。SSR、类型检查和构建不能代替这些验证。
- Telegram 内容为测试字符串，未实际注册或登录账号；未发送消息。
- 没有真实收款、退款、发货、物流查询或供应商采购。
- 未在用户的 Cloudflare 账户或 Windows 电脑执行自助部署脚本。
- 未进行生产容量压测、灾备恢复演练或独立安全审计。

运行时验证使用独立测试数据库。部署升级不会清空已有业务记录或更换加密密钥。正式经营仍需真实商品、可交付账号、收款适配和实际履约验收。
