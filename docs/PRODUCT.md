# 首版产品决策

用户希望由产品经理主动理解需求并实现商城与配套管理系统，指定 Pinxaing 作为专用仓库。仓库初始为空。

## 本轮暂定

- 独立品牌「品享 Pinxiang」，单店数字商品业务。
- 顾客页面面向购买、查询和售后；管理后台位于独立 `/admin`。
- 顾客无需注册即可下单，凭独立订单密钥取货。
- 商品一个规格一个记录，交付方式为库存卡密、下载链接或预约码。
- 先发布仅店主可访问的演示版本，正式收款与公开营业另行验收。
- 复用此前交易基础，但不迁移旧站的订单、库存、密钥、管理员或供应商目录。

商品类型和新旧项目关系的选项未得到用户回答，因此以上为可调整的首版假设。如果改为实物商城，需要新增收货地址、规格库存、运费、发货与退换货模型，而不是只改页面文案。

## 已实现的经营链路

商家创建分类 → 建立商品 → 导入交付库存 → 顾客下单 → 服务端报价与锁库 → 付款核验 → 原子交付 → 客户取货 → 工单售后。

关键经营状态来自数据库，没有伪造成交额、评价、销量或订单。示例商品和测试交易有明显演示标识。

## 后续优先级

1. 确定真实商品、对外品牌、计价与付款渠道，完成实际支付 / 发货验收。
2. 生产容量评估、备份恢复、监控告警和安全审计。
3. 根据运营需要扩展会员、优惠券、通知、批量作业和多规格。
4. 多商户、分销和实物交易需要独立需求与数据模型，不混入首版。
