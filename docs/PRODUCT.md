# 实体商城产品决策

项目中文名称为「品香」，用于前台、后台、邮件和导出文件。GitHub 专用仓库为 `trandainho27-source/Pinxaing`，网站域名为 `pinxiang.lol`，发信子域名为 `auth.pinxiang.lol`。Cloudflare 项目名沿用 `pinxiang-commerce`。

用户明确要求实体物品自助下单、地址与联系方式可空、普通商品整单强制 20 元邮费、仅购买其他商品免邮、付款后显示赠送的加密通讯账号、仅展示发货状态和单号，以及统一预留微信、支付宝、USDT 接口。该要求取代原先“数字商品”的暂定方向。

## 客户购买流程

选商品 → 加入购物车 → 可选填写收货人、地址、联系方式及联系邮箱 → 查看商品金额与适用邮费 → 选择预期付款方式、同意协议 → 提交订单 → 保存订单凭证 → 付款成功后查看赠送账号 → 查询付款与发货信息 → 联系客服或提交工单。

购买无需注册。地址和联系信息留空不阻止下单；发货前由商家与客户沟通补充。系统不会猜测或自动填写地址，也不会因资料留空免除邮费。

## 重要业务约束

- 费用使用人民币分整数：订单总额 = 数据库商品单价 × 数量之和 + 适用邮费。客户端传入的价格、邮费或免邮参数不参与计算。
- 普通商品订单固定邮费以每笔订单计，多件或混合订单仍为 20 元；只有全部商品的 shipping_class 为 other 时免邮。购买时保存每条商品的免邮快照；以后更改商品类型不影响旧订单。配送区域、重量与地址是否填写不改变该规则。
- 赠送账号显示时点为付款成功后。展示名称为「加密通讯账号-极致的隐私与安全」。创建订单只在后台预留一个账号，与商品数量无关；未付款时账号内容不进入接口响应，前台没有查看或复制入口。免费赠送不进入应付金额。
- 店主导入可交付的 Telegram 账号内容，系统负责加密存储、去重与分配，不创建 Telegram 账号，也不承诺普通聊天默认端到端加密。
- 账号分配后仍保留原订单归属，不因取消或过期重新分配，兼容旧版可能已经显示过账号的订单。已付款后登记退款也不回收已展示的凭据。
- 账号不足时不接受新订单，库存和账号分配必须同事务成功或同事务回滚。
- 未付款订单保留 30 分钟，取消或过期释放商品数量；账号仍归原订单。
- 已确认付款的数量计入已售。付款不会自动发货；店主或运营填写物流单号并确认后，配送状态才变为已发货。
- 订单查询依据物流单号展示配送状态：单号为空、仅空白或为「无」时为 `pending`（未发货）；有单号时为 `shipped`（已发货），并展示、支持复制该单号。付款/关闭状态单独显示；取消或退款不伪造“运输中”“已签收”等物流状态。
- 商城没有物流事件查询、快递轨迹或承运商接口。
- 微信、支付宝、USDT 在线接口目前均不可用；本人账号余额可支付订单全额；保存的支付方式只表示客户选择。模拟确认付款仅存在于演示模式。

## 商家管理流程

创建分类 → 上架实体商品（一个规格一条商品）→ 登记数量库存 → 导入赠送账号 → 设置 Telegram 客服用户名 → 跟进客户订单 → 核对收款 → 补充收货资料 → 填单号并确认发货 → 售后与退款登记。

| 权限 | 店主 | 运营 | 客服 |
| --- | --- | --- | --- |
| 商品、分类、实体库存 | 是 | 是 | 否 |
| 赠送账号导入与库存 | 是 | 否 | 否 |
| 订单查看、补充收货信息、工单 | 是 | 是 | 是 |
| 确认收款、登记退款 | 是 | 否 | 否 |
| 发货、单号修正、撤销发货、合并配送、关闭待付款 | 是 | 是 | 否 |
| 内部备注与订单历史 | 是 | 是 | 是 |
| 回收站删除 / 恢复、客户账号状态 | 是 | 否 | 否 |
| 员工、站点设置、支付设置、审计 | 是 | 否 | 否 |

赠送账号的明文不在后台列表、订单详情或操作日志中显示。客户仅在付款成功后凭订单号和密钥或本人登录会话查看账号；订单状态与到账时间必须同时提供付款证据，客户端传入的已付款标记不能解锁。订单凭证在本机记录且可下载，密钥丢失后的人工身份核验和恢复流程尚未实现。

## 升级与范围

保留原私人演示站和 GitHub 仓库，追加数据库迁移，不清空既有数据。旧数字商品不进入当前目录，原订单仍可凭密钥查看历史交付。旧支付和货源路由停止执行，相关模块保留用于历史回归，不代表现行支付已开通。

真实支付、真实商品素材、真实账号、公开营业、生产容量验证、灾备与完整安全审计仍需后续完成。用户已将正式 Cloudflare Worker 接入 `pinxiang.lol`；Sites 体验环境继续保持私人访问范围。

2026-10-17 更正：用户明确要求账号在付款后才可见，取代此前的“创建即显示”规则。此更正采用服务端访问控制，覆盖创建订单响应、重复提交和订单查询；无需清空或重建数据库。

## 邮箱账号与订单管理（2026-10-17）

- 客户页右上角显示「登录」及「订单查询」，不要求登录后购买。邮箱验证码同时用于首次注册与再次登录，无账号密码；验证码 10 分钟有效、单次使用，最多 5 次尝试，发送间隔 60 秒，每邮箱每小时最多 6 次，并有限制来源 IP 的请求频率。
- 邮箱验证成功才创建真实客户账号；演示流程创建独立测试邮箱，不声称已验证真实邮箱，正式环境拒绝该身份。会话使用独立的 HttpOnly、Secure、SameSite=Strict Cookie，有效期 7 天，客户写操作检查来源及 CSRF。
- 登录后新订单由服务端关联当前客户。旧游客订单必须凭订单号与查询密钥主动绑定；不通过联系邮箱自动认领，也不能转移已属于其他账号的订单。
- 账号中心支持本人订单、游客订单绑定、昵称及一组常用收货资料、退出当前或全部设备。常用资料均可留空，下单时点击「使用常用信息」才填入，不修改已创建订单。
- 店主可查看最近 200 个客户账号并停用 / 恢复。停用撤销所有客户会话，但保留独立订单查询凭证；它不是订单凭证吊销功能。
- 店主 / 运营可关闭待付款订单（释放锁定商品），为已付款订单发货、修正单号或撤销发货。撤销发货回到已付款未发货，不回补库存、不撤销付款或赠送内容。不能任意改回待付款。
- 合并的含义是合并配送。2–20 笔已付款待发货订单必须未删除、未合并，同一账号归属、收货人 / 联系方式 / 地址完全一致且完整。合并组的发货、修正与撤销同步所有成员；每笔原订单、金额、原有邮费、付款流水、赠送账号均保留，不自动退款或重算费用。
- 未发货合并组可以整体解除合并。合并订单不可单独修改地址或登记退款；如需处理个别订单，先撤销发货（若有）并解除合并。
- 删除为店主可恢复的回收站，仅允许已发货、已退款、已取消或已过期订单；活动订单先完成或关闭。客户仍可查看自己的订单及有效赠送内容。不会硬删除财务记录或返还已赠送账号。
- 后台支持付款 / 发货状态筛选、按订单号 / 收货人 / 联系方式 / 单号 / 合并组搜索、当前页导出、内部备注和逐单操作历史。备注只在后台显示。关键状态变更使用事务与版本检查，冲突提示刷新。

账号中心尚不提供更换登录邮箱、多个地址簿条目或账号注销。邮件适配器已完成，真实投递仍需运营方提供发件配置并验收。

## 余额、订单通知与商品图片（2026-10-21）

- 联系邮箱选填，与登录邮箱分别保存。填写不赋予订单查询权限，也不自动绑定订单。创建和付款分别生成一条通知；只有真实付款完成才使用「购买成功」。邮件不包含查询密钥、地址或赠送账号。
- 通知事务内入队，配置缺失 / 发送失败不回滚交易。Resend 使用稳定幂等键、冻结请求、租约和最多 6 次重试；超过首次尝试 23 小时转人工核对，避免超出服务方 24 小时去重范围后重复发信。后台店主 / 运营查看状态并重试。服务接收不等同收件箱投递成功。
- 充值采用「选择金额 → 支付 → 服务端确认到账 → 自动增加余额」，无需报备或申请审核。人民币单笔 1–10000 元，最多 5 笔待支付，充值单 30 分钟有效。当前三种外部支付尚未接入，正式充值返回未开通且不创建付款单、不加余额；演示仅允许演示账号模拟。旧版人工申请入口停用，已有记录、余额及流水保留；店主仅可继续处理旧版未结记录。
- 余额只供本人订单全额付款；不混合拆分付款，不提供提现或转账。金额为分整数，每笔充值 / 购买 / 退款保存独立账本；收款流水不得重复用于充值或订单登记。事务内扣款、确认订单及提交库存，失败整体回滚。
- 余额退款需店主确认，实际退回原账户，不能重复退款；合并订单先解除合并。退货入库另行处理，赠送账号保持绑定。
- 商品最多 8 张图片，第一张为主图；可上传 JPG / PNG / WebP（每张最多 5 MB），或填写 HTTPS 链接，支持替换、删除展示和调整顺序。仅店主 / 运营可修改，上传检查来源、CSRF、尺寸和文件头，不接受 SVG。
- 图片文件保存在 R2，D1 仅保存元数据；公开图片 URL 不含桶名和内部键。移除商品展示不会立刻删除 R2 原文件，以免误删其他引用。未配置 BUCKET 时可使用图片链接，后台明确显示上传配置未完成。
- 「其他商品」作为独立前台筛选栏目始终展示；后台邮费规则选择「免邮 · 加入免邮商品栏目」即可加入。原有商品默认普通，不批量改变已有商品与订单。

## 自定义目录与直接充值（2026-10-21 补充）

- 分类名称、商品标签均可编辑；置为推荐的商品也优先展示商家填写的标签。分类 / 商品图标支持通用图标和最多 8 个字符的自定义文字或表情；商品图片优先，图标不决定类别或邮费。
- 站点设置可编辑首页主标题、商品列表标题和免邮栏目名称；只更正仍与旧默认完全相同的宣传语，保留商家自定义内容和商品。
- 在线充值状态只能由服务端核验付款凭证后入账。核对方式、金额、币种和有效付款时间，唯一流水与事务账本保证重复通知不重复增加余额。未接入支付适配器前正式入口保持关闭；仅写变量不会开通。晚到通知允许实际付款发生在有效期内，异常通知不入账。
- 后续支付适配器必须先核验签名 / 服务方查询、商户归属、实际资金金额、币种和时间，再调用内部入账方法；USDT 需锁定网络及兑换报价。浏览器提交的 paid 字段不能作为凭证。
