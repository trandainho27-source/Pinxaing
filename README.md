# 品香 Pinxiang · 实体商品自助商城

实体商品售卖网站与配套管理后台，项目专用仓库：**trandainho27-source/Pinxaing**。正式域名为 `pinxiang.lol`，由用户的 Cloudflare Worker 承载；私人体验站保留独立数据库与配置。体验站示例商品不产生真实配送，赠送账号是不能登录 Telegram 的测试内容。

## 本版交易规则

| 功能 | 实现规则 |
| --- | --- |
| 实体商品 | 商品、分类、价格、图片链接、购买数量限制与数量库存 |
| 收货资料 | 收货人、地址、联系方式均可留空；商家可在发货前补充 |
| 固定邮费 | 每笔订单自动加收 **20 元**，不可取消；后端重新计算价格，多个商品也只收一次 |
| 随单赠送 | **付款成功后才显示「加密通讯账号-极致的隐私与安全」**，未付款时不返回账号内容 |
| 赠送账号来源 | 店主批量导入，按账号标识去重，AES-GCM 加密保存；系统不自动注册账号 |
| 账号与库存 | 商品下单锁定，30 分钟未付款释放；已经展示的赠送账号不因取消或过期而回收 |
| 付款与发货 | 确认收款后仍为未发货；填写物流单号并确认发货后才为已发货 |
| 配送展示 | 单号为空或为「无」显示未发货；有单号显示已发货及单号，没有物流轨迹、节点或查询服务 |
| 支付方式 | 微信、支付宝、USDT 统一预留，**全部尚未接入** |
| 查询与售后 | 右上角「订单查询」；游客凭订单号和密钥查询，登录客户可直接查看本人订单 |
| 客户账号 | 右上角醒目「登录」，邮箱验证码注册 / 登录、订单绑定、常用信息、退出所有设备；登录为可选项 |

后台包括库存调整、赠送账号管理、订单多条件筛选与当前页 CSV 导出、收货信息补充、收款 / 退款登记、发货及单号修正、撤销发货、合并 / 解除合并、订单回收站、内部备注、客户账号管理、客服工单、员工权限和操作日志。顾客前台不展示后台入口。

账号池为空时停止新下单，以保证每笔成功订单都能获得赠送账号。开店前应准备足够的账号，并在「站点设置」填写 Telegram 客服用户名。

## 技术与验证

React + TypeScript + Vinext / Vite，运行在 Cloudflare Workers，业务数据存储于 D1。价格使用人民币分整数；订单、实体库存预留和赠送账号预留在同一事务内完成；账号仅在服务端确认已付款后解密并返回。下单凭证支持重复请求幂等，后台使用 HttpOnly 会话、来源校验和 CSRF。

使用 Node.js 24：

```bash
npm run install:ci
npm run typecheck
npm test
npm run build
npm run verify:worker
```

81 项测试包含 18 项邮箱账号 / 订单管理检查、25 项实体交易及升级兼容检查、38 项保留的历史模块回归。编译后的 Worker 在 workerd 中验证演示与正式配置流程；所有业务验证均使用隔离的测试数据库，不涉及真实付款、物流或 Telegram 登录。详情见 [验收记录](docs/VALIDATION.md)。

## 客户邮箱登录

已实现邮箱验证码注册 / 登录。运行时需配置 `RESEND_API_KEY`、`EMAIL_FROM`，并沿用有效的 `INVENTORY_KEY`。店主在后台「客户账号」查看逐项配置诊断，完成实际收信与登录后再确认正式可用。当前私人演示站尚未配置发信服务，因此真实邮箱验证暂不可用；可在登录页体验明确标注的演示验证码。演示账号不会被标记为真实邮箱已验证，正式环境拒绝演示身份。详见 [邮箱配置](docs/EMAIL.md)。

## 当前范围与后续接入

微信、支付宝、USDT 的付款创建、查询和回调均保留入口但不处理资金。旧版 TRC20 / HMAC 支付与数字货源模块只为历史代码兼容保留，新业务路由不会调用它们，旧环境变量也不会启用收款或采购。

退款操作仅登记已完成的退款，不自动退款或回补库存。多规格当前采用“一种规格建立一个商品”；暂不包含多商户、会员钱包、优惠券、自动退换货流程。合并发货组可统一登记和修正物流单号，保留每笔原订单费用及赠送账号。上线经营仍需真实商品、赠送账号、收款接入和实际履约验收，以及容量、安全和灾备验证，不能把演示测试视为完整企业级生产验收。

数据库升级采用追加迁移，保留旧订单及其凭证查询；历史数字商品不再进入新商城目录。正式环境默认不创建示例商品或默认管理员。生产与演示数据库应保持隔离。
